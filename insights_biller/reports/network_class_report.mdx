#### Summary

The **Network Class Report** is a per-payer, per-procedure breakdown of revenue activity for a chosen site over a chosen date window. For every encounter line item, it shows which payer was billed, how much was charged, paid, and adjusted, and — critically — whether the claim was **auto-forwarded** from a previous payer (i.e. a ghost claim) and which payer it was forwarded from.

<Warning>
The financial columns (`charges`, `paid`, `total_adjustments`) are **lifetime-to-date** values for each encounter line, not period-windowed. The date range filter controls *which encounters appear*, but the dollar amounts reflect the full cumulative history of each encounter. For period-windowed dollar amounts, use the [Revenue Activity Report](/insights_biller/reports/revenue_activity_report) instead.
</Warning>

#### Key Use Cases

- Understand how revenue is distributed across network classes and payer types.
- **Auto-forward audit.** Filter `autoforwarded = Yes` to see every secondary/tertiary line that was forwarded automatically, paired with `autoforwarded_from_payer` to know where it came from — useful for verifying that auto-forward logic sends claims to the right downstream payer.
- Compare billed vs. net collected amounts by payer group.
- Identify payers or network classes with disproportionately high adjustment rates.

#### Data Dictionary

| Column Name | Description |
| --- | --- |
| encounter_id | The encounter the line item belongs to. |
| payer (submitted_inputted_insurance) | Payer name as inputted at the time the claim was submitted. |
| procedure_id | Procedure within the encounter. |
| payer_index | 1 = primary, 2 = secondary, 3 = tertiary, 4 = self-pay. |
| billed_insurance | Payer name from the latest claim submission (the current mapped name on the most recent claim). |
| charges | Lifetime-to-date billed amount attributable to this payer on the encounter. Not windowed to the date range. |
| paid | Lifetime-to-date amount this payer has paid on the encounter. Not windowed to the date range. |
| total_adjustments | Lifetime-to-date contractual + other adjustments on this encounter line. Not windowed to the date range. |
| autoforwarded | Yes / No — was this payer's claim an auto-forwarded ghost claim (the system carried the balance forward to this payer instead of an operator submitting an independent claim)? |
| autoforwarded_from_payer | If `autoforwarded = Yes`, the payer the claim was forwarded from (the parent claim's mapped insurance company). Blank otherwise. |

#### Filters Supported

- Date Range — filter by encounter from date (controls which encounters are included; does not window the financial figures)
